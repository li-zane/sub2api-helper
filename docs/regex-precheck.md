# 前置正则降智检测

入口：**降智检测设置 → 前置简单检测**。默认关闭，已有糖果／指纹流程保持原有行为。开启后，手动检测、定时检测和导入后的一次检测都先执行前置步骤。

可设置独立的模型、完整提示词、正则表达式及 `i` / `m` / `s` / `u` 标志。正则填写表达式本身，不含两侧 `/`。模型沿用该账号的模型别名映射和固定出口。

每个远端账号只发送一条前置用户消息，`store: false`，不传入历史消息、`previous_response_id` 或 conversation ID，也不复用前一阶段的回复。即使重试或进入糖果／指纹，后续请求仍各自独立。

## 结论与兜底

| 前置结果 | 后续行为 | 本轮最终结论 |
| --- | --- | --- |
| 未降智，勾选“跳过兜底” | 结束本轮，不加载指纹参考库、不请求兜底模型 | 前置通过（`match`） |
| 未降智，未勾选“跳过兜底” | 按原轮换进度执行糖果或指纹 | 使用兜底结论 |
| 疑似降智 | 按原轮换进度执行糖果或指纹 | 使用兜底结论，前置疑似结果不覆盖它 |
| 请求错误、空回答、未完成回答、正则执行异常 | 记录异常，结束本轮；原有凭据/额度异常处理继续生效 | 不按“未命中”判为降智或通过 |

“降智判断条件”可选 **命中正则时疑似降智** 或 **未命中正则时疑似降智**。只匹配完整的模型回答正文，不匹配思考过程、错误消息或历史记录。

同一逻辑账号有多条远端记录时，所有前置结果通过才能跳过兜底；任一明确疑似降智则对这些记录执行原有兜底。最终结果才进入分组、并发、优先级、质量历史和 IP 轮换等现有联动。前置的疑似结论本身不会提前触发这些动作。

## 轮换与历史

每轮完成检测都推进糖果／指纹进度，前置通过而跳过兜底也计一轮。例如糖果 1 轮、指纹 1 轮：第一轮前置通过、跳过糖果；第二轮若需要兜底则执行指纹；第二轮也跳过时，第三轮回到糖果。完成条件沿用原规则：完整糖果回答消耗轮次，网络／授权失败或未完成的检测保留轮次。多份样本及其重试合计只推进一轮，进度跨重启保存。

前置开关或规则修改会使旧检测结论失效，取消正在使用旧规则的检测，但保留兜底轮换位置。设置和进度均跨重启保留。

最近 6 轮记录区分“前置正则”“糖果”和“指纹”。进入兜底的记录会分别展示前置与最终结果；展开“Prompt 与回答”可看各阶段原文、重试、耗时与 Token 用量。列表只加载摘要，原文按需读取。

前置请求共用现有“检测失败重试”的次数与间隔，只重试可重试的临时请求错误；明确匹配结果、正则执行异常不重复采样。未完成的流式回答即使包含匹配值也不参与判断。

## 设置 API

沿用管理员鉴权的 `POST /api/model-fingerprint/settings`，`patch.precheck` 支持嵌套增量更新，省略字段保留已有值。下面的简单算术示例用于说明字段配置：

```json
{
  "patch": {
    "precheck": {
      "enabled": true,
      "model": "MODEL_ID",
      "prompt": "计算 2+2，只输出结果，不加解释。",
      "pattern": "^\\s*4\\s*$",
      "flags": "",
      "degradedWhen": "no_match",
      "skipFallbackOnPass": true
    }
  }
}
```

仍需配置糖果／指纹的检测模型与轮换次数，以供兜底。前置提示词最多 16000 个字符，正则最多 2000 个字符；匹配回答最多 262144 个字符。正则在独立工作线程中执行，超时会终止匹配并保留异常记录。
