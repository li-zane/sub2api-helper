# 使用与配置指南

[返回功能介绍](../README.md) · [自动化说明](automation.md) · [任务设置](automation.md#任务设置与默认值)

## 环境要求

- Node.js 22 或更高版本（模型指纹检测 SDK 要求 Node.js 22+）。
- Python 3.9 或更高版本；默认协议登录流程需要安装 `curl_cffi`（浏览器 TLS 指纹请求库），即使不使用代理也需要。
- macOS 使用 Keychain（钥匙串）持久保存密码、2FA 密钥和账号代理。
- Windows 使用当前用户的 DPAPI（数据保护接口）加密保存上述数据，密文位于 `%LOCALAPPDATA%\toSub2\credentials`，只能由同一个 Windows 用户解密。
- Linux 可通过 `TOSUB2_CREDENTIAL_KEY` 启用 AES-256-GCM（高级加密标准）加密文件保存密码、2FA 密钥和账号代理；该变量必须是随机 32 字节密钥的 64 位十六进制或 Base64 表示，并由部署环境通过受限环境变量或 secret（密钥管理）注入，程序不会把它写入任务目录。未配置密钥时仍可使用邮箱验证码流程，但凭据和代理不会跨服务重启持久化。

Linux 生产服务建议把凭据目录放在服务数据目录（例如 `/var/lib/tosub2/credentials`），并同时配置：

```bash
TOSUB2_LINUX_CREDENTIAL_ROOT=/var/lib/tosub2/credentials
TOSUB2_CREDENTIAL_KEY=<64 位十六进制随机密钥>
```

## 安装与启动

```bash
git clone https://github.com/li-zane/sub2api-helper.git
cd sub2api-helper
npm install
python -m pip install -r requirements.txt
npm run dev
```

默认访问地址：

```text
http://127.0.0.1:4399
```

指定其他端口：

```bash
npm run dev -- --port 4400
```

允许局域网设备访问：

```bash
npm run dev -- --host 0.0.0.0
```

局域网模式没有访问认证，只应在可信网络内短时间使用。

### PM2（Node.js 进程管理器）守护运行

号池巡检依赖控制台服务持续运行。需要崩溃后自动重启或开机启动时，建议使用项目内置的 PM2 配置：

```bash
npm install -g pm2
npm run daemon:start
pm2 save
pm2 startup
```

`pm2 startup`（生成开机启动配置）会输出一条系统命令，继续执行该命令即可。默认使用 `127.0.0.1:4399` 和项目内的 `tmp/chatgpt-onboarding-console` 数据目录。

需要保留旧数据目录并开放局域网时，macOS/Linux 可以在首次启动时传入：

```bash
ONBOARDING_OUTPUT_ROOT=/path/to/existing-data ONBOARDING_HOST=0.0.0.0 npm run daemon:start
```

Windows PowerShell（命令行）使用：

```powershell
$env:ONBOARDING_OUTPUT_ROOT="C:\path\to\existing-data"
$env:ONBOARDING_HOST="0.0.0.0"
npm run daemon:start
```

常用管理命令：

```bash
npm run daemon:restart
npm run daemon:logs
npm run daemon:stop
```

PM2 只负责在进程异常退出后重启。toSub2 在正常关闭时仍会先取消巡检请求、停止登录任务并保存任务状态。

任务设置保存在数据目录的 `task-settings.json`。账号代理分配支持“全局代理”“Sub2API 均衡分配（登录前绑定）”和“动态登录 + 按 PlanType 授权”。旧 Sub2API 模式仍在登录前按出口 IP 的账号数分配并绑定；新模式仅在账号尚未绑定代理时使用全局动态代理首次登录 ChatGPT 网页，读取当前工作空间的 PlanType 后，按对应的 Sub2API 方案分配并持久绑定 IP；后续操作优先复用绑定；网页登录确认 PlanType 变化后重新应用对应方案，并同步号池绑定。只有方案代理选择“均衡分配（toSub2）”的账号参与自动分配。没有保存过并发 UI 设置时，可以用 `TOSUB2_MAX_ACTIVE_JOBS` 指定初始值（1–20）；保存后的 UI 设置优先于环境变量。`GET /api/task-settings` 和 `POST /api/task-settings` 使用控制台令牌读取或保存设置。任务 API 的 `startedAt`、`durationMs` 可用于观察每次任务取得槽位后的耗时，排队时间不计入。任务设置还可以保存 `autoActions`（PlanType 到 `upload`、`rotate-logout-reauthorize-upload` 的数组），批量导入触发的授权完成并识别到对应 PlanType 后由服务端自动执行；没有匹配规则的 PlanType 不会自动执行其它操作。

## 账号代理和 TLS 指纹

网页顶部的“代理 IP”输入框配置账号登录使用的代理。支持以下格式：

```text
http://用户名:密码@主机:端口
socks5h://用户名:密码@主机:端口
socks5h://account-id:proxy-secret-JP-91977332-20m@proxy.example.com:1000
```

如果用户名中存在 `-sid-xxxxxxxx-t-20`，或者密码中存在 `-JP-12345678-20m` 这样的会话字段，toSub2 会按既定代理策略为任务准备代理会话，并使用 `curl_cffi` 检测连接。账号 Web 登录的浏览器身份按规范化邮箱单独持久化到运行数据目录的 `browser-identities/`：不同账号使用不同设备 ID，同一账号在重新登录、重试和服务重启后复用同一个设备 ID、User-Agent、Client Hints 和 TLS profile。新身份默认 `chrome142`，可在首次创建前用 `--tls-profile` 或 `TOSUB2_BROWSER_TLS_PROFILE` 指定；已有身份不会随全局 TLS 探测结果改变，指定 profile 不受支持时直接报错，避免自动换浏览器。代理出口仍遵循现有绑定、轮换和重试策略；网络错误不会重新生成浏览器身份。

代理首次检测通过后，正式登录和授权流程如果再次遇到明确的安全校验页面，会先保持当前代理出口重试最多 3 次；手机号验证码发送接口只有在 `400/409` 同时带有安全校验响应头或实际安全校验页面时才采用相同策略。连续 3 次重试后仍然触发风控，才会进入更换代理并重新授权流程。普通手机号不可用、`invalid_state` JSON 等业务错误不会触发代理重试，只提示用户更换当前手机号。

当响应包含可执行的 Cloudflare（云防护平台）挑战配置时，toSub2 会优先在当前 `curl_cffi` Session（会话）中运行父挑战和 Turnstile（人机验证）子挑战。获得 `cf_clearance` 后会使用同一代理出口、同一 TLS 指纹和同一 Cookie 会话重放原请求。只有挑战无法完成或重放后仍被拦截时，才进入上述同出口重试和随机会话编号兜底。该运行环境依赖 `jsdom`（网页环境模拟器），执行 `npm install` 时会自动安装。

Sentinel（动态安全令牌）不再使用项目内置的静态 PoW/DX 生成器。每个登录会话会实时下载 Sentinel 加载器和当前版本 SDK，在独立的 `jsdom` 父页面和 iframe（内嵌页面）中执行，并由当前 Python `curl_cffi` Session 提交 SDK 产生的请求。生成过程复用账号当前代理、Cookie、设备 ID、TLS 指纹、User-Agent 和平台语言信息；代理会话或 `sid` 更换后会销毁旧 Sentinel 运行时并重新初始化。最终按服务端要求生成 `OpenAI-Sentinel-Token`，存在 Session Observer（会话观察器）数据时同时生成 `OpenAI-Sentinel-SO-Token`。

代理 IP 和“代理失败时允许回退本地出口 IP”开关通过“保存代理配置”写入服务端运行数据目录的 `task-settings.json`（权限 `0600`），刷新页面、切换浏览器或重启服务后恢复。输入框修改后需要保存才会用于任务；多个浏览器共用服务端配置，其他页面约每 15 秒读取最新配置。该文件可能包含代理用户名和密码，应作为敏感配置保护。旧版浏览器 localStorage 中的代理不会自动覆盖服务端配置，需要手动填写并保存一次。

在“代理 IP 配置 → 出口与纯净度检测”中，可检测已保存的全局代理，或逐个检测第二、第三种模式中的 Sub2API 代理节点。两次请求均通过该代理访问 IPify，显示实际出口 IP、平均 HTTP 请求耗时、成功次数及出口是否一致；随后按观测到的 IP 查询 proxycheck.io，展示地区、运营商、ASN、网络类型、代理/VPN/Tor/机房标记及 0–100 风险分。风险分越低风险越低，0–33 为低风险、34–66 为中风险、67–100 为高风险；缺少分数或信誉库限额、超时时显示未知，出口检测结果独立保留。信誉记录缓存 10 分钟并标明查询时间。结果反映检测时的出口与该信誉库记录。

检测使用独立连接：全局代理每次点击检测时轮换一次可识别的会话编号（用户名 `sid` 或支持的 Kookeey 密码会话格式），同次检测的两次抽样共用这个新会话；Sub2API 节点始终保持配置的固定会话。结果标明本次是否轮换，未识别到会话参数的全局代理会按原地址检测。轮换会话后实际出口由代理服务商分配，观测到的不同出口分别展示信誉结果。检测不回退直连，不登录账号、不改变保存的代理模板或账号绑定；未保存的全局代理需先保存后检测。`POST /api/proxy-quality/check` 使用控制台令牌，接收 `{ "target": "global" }` 或 `{ "target": "sub2api", "proxyId": 123 }`，由服务端按目标决定是否轮换；结果包含 `sessionRotation`（`rotated`、`fixed` 或 `unsupported`），不返回代理认证信息。可运行 `npm run test:proxy-quality` 验证检测流程。

“Codex 状态”列有独立的“过载”和“冷却”开关。在“任务设置 → 号池与用量同步”中设置调用与过载统计间隔（默认 60 秒）和网络并发（默认 100）。曲线每格的长度跟随“过载 → 自动冷却”中的统计窗口，默认 15 分钟一格，显示 `00–15、15–30、30–45、45–00`，共 6 格、刻度跨度 90 分钟；19 分钟同步时，`15–30` 这一格只累计到 19 分钟。窗口改成 30 分钟时显示 3 格；不能整除 90 分钟时，按完整格向上取整并标出实际跨度，大于 90 分钟时显示 1 格。两条曲线分别统计请求次数和指定 503 过载次数。首次同步填充历史，之后通常只重查当前格与上一格；断档时补齐缺失区间，每小时完整校对延迟写入的日志。窗口、号池账号集合或后端变化时重建统计，旧次数不会套用到新标签。单项同步失败保留同区间的缓存和各自的成功时间，缓存跨重启保留。左侧能量条使用当前固定格的次数，右侧使用图表所有格的累计次数；冷却同时检查两项阈值，复用同一次采集和历史缓存。旧版默认的 900 秒同步间隔迁移为 60 秒，其它自定义间隔保留。

在“任务设置 → 过载 → 自动冷却”中设置统计窗口、过载次数阈值和冷却时长，默认每 60 秒随次数同步检查当前 15 分钟固定格和 90 分钟图表累计，当前格达到 10 次，或累计达到 30 次，任一满足就冷却 60 分钟；新账号默认关闭。达到阈值后将该账号原本启用的 Sub2API 记录设为暂停分配，到期只恢复本功能暂停的记录。冷却与曲线共用采集频率，但“冷却”可单独开启，不依赖“过载”展示开关；仅开启冷却时只采集过载日志。暂停/恢复并发在“冷却操作并发”中展开。统计与冷却只读取号池已有日志，不主动调用模型。累计数据不完整时只判断当前格；采集失败不会使用旧次数触发冷却。恢复当格跳过旧次数，下一固定格重新检查两项阈值；累计仍超限会再次冷却。

在“任务设置 → 批量导入后的自动任务”中，每个 PlanType 预设可以单独勾选“自动开启过载冷却”（`enable-overload-cooldown`）。批量导入账号授权完成后按其 PlanType 开启账号的冷却开关，使用上方统一配置的冷却规则；它与“自动开启过载统计”（`enable-overload-detection`）分别设置，可以独立使用。配置了上传或轮换上传时先完成这些动作，再开启统计和冷却。未匹配预设的账号保留现有开关状态。

自动冷却只调整号池分配开关，保留登录、令牌与 IP 绑定；恢复后从恢复时刻重新计数。冷却截止时间和待恢复记录保存在 `overload-cooldown.json`，重启后继续执行，接口失败时保留状态并重试。手动禁用优先，关闭自动冷却会恢复本功能仍负责的暂停记录。`POST /api/jobs/:id/overload-auto-cooldown` 接收 `{ "enabled": true }` 或 `false`；全局规则通过任务设置的 `overloadAutoCooldown` 字段保存。可运行 `npm run test:overload-cooldown` 验证状态恢复与号池控制。

配置了全局代理后，新建任务、重试、重新授权，以及号池异常监测触发的自动重新登录均优先使用已保存的全局代理。页面执行任务不再提交输入框的代理值，因此空输入框不会清除账号代理。未配置全局代理时保留账号原有代理，没有账号代理时使用服务器出口 IP。账号代理仍保存在系统安全凭据存储中；代理密码不会写入 `job-meta.json`（任务元数据）或日志。

本地出口回退默认关闭：代理不可用时任务停止，不会改用服务器出口。开启后，固定代理检测失败或轮换代理达到重试上限时，本次任务允许回退服务器出口 IP 重试一次；不会删除已保存的代理，下次重新登录仍先尝试代理。密码错误、账号封禁等业务错误不会触发出口回退。

Python 辅助进程默认使用 `python3`（macOS/Linux）或 `python`/`py -3`（Windows）。如果系统有多个 Python，可以设置环境变量 `TOSUB2_PYTHON` 指定解释器路径。

### Codex 授权来源

在“任务设置 → Codex 授权方式”中选择凭据生成方式，保存后对后续开始的登录、重新登录和重新授权生效；正在运行的授权沿用启动时的方式，设置在服务重启后保留。

- **本地授权（默认）**：toSub2 生成 OAuth 链接、维护 PKCE 状态并直接兑换或刷新令牌。
- **Sub2API 授权**：复用已保存的 Sub2API 后端地址与管理员 API Key，调用 `POST /api/v1/admin/openai/generate-auth-url` 取得授权链接和 `session_id`。toSub2 完成登录及授权回调后，将 `code`、`state` 和会话 ID 交给同一后端的 `exchange-code` 接口兑换凭据；重新授权优先调用该后端的 `refresh-token` 接口。

Sub2API 模式需要后端支持上述接口。账号代理模式会在链接生成、令牌兑换和刷新时传递已绑定的 `proxy_id`；全局代理需要与 Sub2API 中可用代理的连接地址一致，否则任务显示配置错误。匹配后的全局代理在本次授权中同样固定，不自动轮换或回退直连。未配置代理时两端使用各自的直连出口；如需同一出口，请启用账号代理模式。远端刷新由 Sub2API 执行，不额外探测 toSub2 的登录代理；明确返回刷新令牌失效时，自动重新登录并继续使用 Sub2API 授权。

新方式复用现有本地凭据导出及号池更新机制，重新登录、冷却恢复和切换 IP 后仍会更新已有号池账号。授权提供方的会话与 PKCE 状态分开保存，切换方式或后端后，保留可用的登录会话并重新开始对应提供方的授权。后端接口错误会显示失败信息，未完成的授权不覆盖原凭据。

### Sub2API 账号代理与批量维护

按 PlanType 选择代理时，先在“代理 IP 配置”中保存用于网页登录的动态代理，在“Sub2API 设置”中按方案绑定 PlanType，并选择“使用账号原配置”“指定代理”“直连”或“均衡分配（toSub2）”，最后在“任务设置 → 账号代理分配”选择“动态登录 + 按 PlanType 授权”。首次网页登录与 Codex 授权共用已验证的 Cookie；识别 PlanType 后只分配并保存一次代理。后续网页登录、授权链接、令牌兑换、刷新、2FA/密码维护及号池同步都使用该绑定；重新导入、修改方案、订阅类型变化和服务重启均保留绑定。节点失效或记录的出口 IP 改变时停止任务并保留原绑定，可修复代理或手动切换 IP 后继续。未识别当前工作空间或 PlanType 时停止授权并保留登录断点。未绑定方案的 PlanType 使用当前方案；“使用账号原配置”保留已有号池代理，新账号没有原代理时直连。

均衡分配按出口 IP 的账号总数选择当前最少的一侧，同一出口的多个节点合并计数，并发任务预留分配数量。已有绑定在重新登录与服务重启后保留。账号列表的“绑定 IP”列展示 Sub2API 代理备注名称和出口 IP；尚未上传的账号展示本地授权绑定，未绑定和直连有单独标记。第二、第三种模式的“代理 IP 配置”均展示各出口 IP 的账号数量，同出口节点合并展示，直连单独计数。Sub2API 配置中的 `balanced` 是 toSub2 专用标记，写入号池前转换成实际数字代理 ID。原“Sub2API 均衡分配（登录前绑定）”模式仍可单独选择。

账号的登录、重新授权及号池凭据更新均沿用绑定代理；方案中的统一代理设置不覆盖该绑定。此模式保持代理原有会话编号，不自动轮换或回退直连。绑定节点失效时显示错误，修复代理或使用“一键切换 IP”后继续。代理凭据保存在本机安全凭据存储中，绑定 ID、冷却截止时间和同步状态保存在任务元数据中。

选中多个已授权且空闲的账号后，可以使用：

- **一键重登**：弹窗输入冷却时间（默认 0 分钟，范围 0–43200）；登出全部设备后按需等待，再重新登录 Web、完成 Codex OAuth，并原位更新 Sub2API 号池凭据，全程保持原 IP 绑定。冷却期间释放登录并发，服务重启后恢复截止时间，取消任务则停止后续登录。无需在任务设置中指定统一冷却时长。
- **一键切换 IP**：按当前绑定数量为账号选择不同出口 IP，登出全部设备，再通过新代理登录授权并更新号池。没有不同的可用出口时返回失败信息。

普通“重新开始授权”、单个或批量“重新授权”成功后，也会自动更新号池凭据。登录失败时保留错误状态；授权成功但号池暂时不可用时保留待同步状态，每分钟重试同步，重启后继续，不重复登录。需要邮箱验证码或 2FA 验证时，继续使用现有的自动收码或手动输入流程。

## 批量添加格式

每行一个账号。toSub2 会根据字段特征自动识别邮箱、密码、邮件接收 API 和 2FA 密钥，字段顺序不固定。现有 `----` 格式仍完全兼容：

支持 `邮箱----密码----2FA密钥(备注)`，例如 `name@example.com----账号密码----JBSWY3DPEHPK3PXP(首批账号)`；紧跟 2FA 字段的英文或中文括号内容会保存为备注，密码中的括号仍按密码处理。重复导入时省略备注会保留原备注。账号行下方的“添加备注”或现有备注可以点击编辑，支持多行文本，最多 2000 字。本地 `remark` 与号池 `notes` 双向同步：导入或保存会更新同邮箱全部号池账号的完整备注，清空也同步；在号池修改或清空后，页面约每 15 秒同步回显并持久保存。保存失败的本地内容会保留为待同步状态，后续同步自动重试，服务重启后仍保留。编辑弹窗中的草稿不会被轮询覆盖。历史同邮箱重复账号的备注不一致时，优先采用本次发生变化的记录，再按 `updated_at` 和账号 ID 确定来源；没有变化时保留已选内容，避免来回切换。尚未进入号池的账号在上传或下载 JSON 时带上备注；多行备注请通过 JSON 下载保留，单行备注也可随原始账号文本导出。

```text
邮箱
邮箱----邮箱收码接口
邮箱----密码
邮箱----密码----2FA身份验证密钥
邮箱----密码----邮件接收API
邮箱----密码----邮件接收API----2FA身份验证密钥
邮箱----邮箱收码接口----2FA身份验证密钥
邮箱--------2FA身份验证密钥
```

示例：

```text
name@example.com
name2@example.com----https://mail.example/messages/account-token
name3@example.com----账号密码----JBSWY3DPEHPK3PXP
name4@example.com----账号密码----https://mail.example/messages/name4
name5@example.com----账号密码----https://mail.example/messages/name5----JBSWY3DPEHPK3PXP
name6@example.com----https://mail.example/messages/account-token----JBSWY3DPEHPK3PXP
name7@example.com--------JBSWY3DPEHPK3PXP
```

也可使用 `|`、Tab（制表符）、`::`、逗号、分号或连续空格分隔，例如：

```text
https://mail.example/messages/name|JBSWY3DPEHPK3PXP|账号密码|name@example.co.uk
JBSWY3DPEHPK3PXP::name+tag@example.dev::账号密码
```

解析器会先确定完整 URL（网址）、独立邮箱和 Base32（基础三十二进制）2FA 密钥，然后根据它们的边界推断分隔符，将剩余原文作为密码。因此密码内包含 `|` 等字符时也会尽量完整保留。邮箱中的合法短横线也会尽量合并回完整邮箱，不会直接把邮箱前半部分当成密码。如果一行存在多种可能的拆分方式、多个完整邮箱、URL 中的逗号或分号可能被当成字段分隔符，会明确报错并提示改用 `----`，不会静默猜测。仅有邮箱和 2FA 密钥的账号继续使用 `邮箱--------2FA密钥` 表示空密码；`邮箱----密码--------2FA密钥` 也会正确识别密码和 2FA。仅有邮箱、一个 Base32 字段和邮件 API 时，Base32 字段在 API 之前按密码保留，在 API 之后按 2FA 密钥处理；如果同时还有另一个普通字段，则 Base32 字段按 2FA。单独出现的 `http://` 或 `https://` 字段按邮件 API 处理，不支持自动区分“网址形式的密码”。邮箱支持多级域名及点、短横线、下划线、加号等常见前缀，不限制为 `.com` 后缀。邮箱是唯一字段，重复导入会更新原任务资料。

## 接码平台配置

网页顶部的“接码平台”区域可以打开统一配置页面。每个平台拥有独立配置，保存后写入当前浏览器的 localStorage（本地存储）；服务端不会持久保存 API Key（接口密钥）。

目前支持：

- LubanSMS：填写 API Key 和供应商编号。
- SMSBower：填写 API Key 后手动点击“查询价格”，再从下拉框选择国家。列表按价格从低到高显示中文国家名称、价格和库存，不显示国家缩写和国际区号。
- 自定义接码：每行填写 `+国际手机号----接码API`，一次最多 500 条。重复手机号以最后一行为准，并发任务按顺序获取未分配号码。

```text
+8613711111111----https://example.com/messages/13711111111
+8613822222222----https://example.com/messages/13822222222
```

任务到达手机号步骤后，可以使用当前选中的平台取号。SMSBower 取号时会带上用户选择时的最高价格，避免实时价格上涨后按更高价格购买。自定义接码在发送短信前会先记录接口中的旧验证码，只提交之后出现的新验证码。服务端会自动轮询短信、提取独立的 6 位数字验证码并提交。手动手机号和手动验证码流程始终保留。

新增平台时，通过统一 SmsProvider（短信平台适配器）接入，不需要复制任务轮询和状态处理代码。

API Key 只会随取号请求临时发送给本地服务，不会写入任务元数据、协议日志或导出文件。

## 直接上传到 Sub2API

任务完成后，可以在单个任务的“上传”按钮，或顶部批量操作中使用“上传到 Sub2API”，把生成的 OAuth（授权）账号直接写入指定的 Sub2API 后端号池。

首次使用时，在页面的“Sub2API”配置区域填写：

- Sub2API 后端地址，例如 `http://127.0.0.1:8080`。
- 管理员 API Key（管理员接口密钥）。请求时通过 `x-api-key` 请求头发送。
- 点击“读取配置”后读取目标号池和代理列表。目标号池支持 OpenAI 与 Composite 平台分组多选；不选择具体分组时使用后端默认号池。
- 可以统一指定代理 IP、并发数、负载因子和优先级。数字参数留空时保留每个账号原来的配置。
- 可以设置账号命名模板，例如 `chatgpt-{email}`；支持 `{email}`、`{planType}`、`{planType_disp}`（当前 PlanType 映射值）、`{accountId}` 和 `{name}`，留空时保留导入文件中的原名。模板在服务端上传前渲染，批量上传和单个上传使用同一规则。
- 配置方案内部可开启“按导入日期设置优先级”，并指定 `0–10000` 内的闭区间。每个方案独立计算，绑定该方案的所有 PlanType 共用同一套导入日期排序，不再按 PlanType 分开计算。按上海时区从早到晚分组，同日账号使用同一优先级，计算值为 `min(上限, 下限 + 日期序号)`（序号从 0 开始）。例如范围 `2–5`，两条 13 日账号都为 2，三条 14 日账号都为 3，第 4 个不同日期及之后统一为 5。导入时间优先取号池 `created_at`，缺失时取本地首次导入时间；缺少有效时间的账号保留原优先级。未绑定 PlanType 的账号沿用当前方案回退规则并参与该方案排序；开启时优先于固定优先级，保存设置、上传、状态同步及巡检会重新计算，账号增加、删除或方案绑定改变后会按新的日期集合重排。关闭后回到原优先级配置逻辑，不自动恢复历史手动值。
- 可以填写允许使用的模型，每行一个，也支持逗号分隔，例如 `gpt-5`、`gpt-5-mini`。
- 可以设置账号级 `WS mode`：`off`、`ctx_pool`、`passthrough` 或 `http_bridge`。该设置会写入 OpenAI OAuth 账号的 `extra.openai_oauth_responses_websockets_v2_mode` 及对应启用开关，并在上传和号池自动修复时保持一致。使用非 `off` 模式前，需要在 Sub2API 的 `gateway.openai_ws.mode_router_v2_enabled` 中启用新版路由。
- 可以新增多个配置方案。管理地址、管理员 API Key 和自动检测开关是全局设置；号池、代理、并发、负载因子、优先级、账号命名模板、模型白名单、Codex 指纹模式和 WS mode 由每个方案独立保存。可把任意原始 `PlanType` 绑定到方案，例如 `self_serve_business_prolite` -> Business Premium、`free` -> Free。上传时同一批账号会按绑定方案分组调用 Sub2API。
- 保存 Sub2API 配置时，如果某个已绑定方案的参数有变化，服务会立即读取号池账号列表，把改动的字段通过 `PUT /api/v1/admin/accounts/:id` 推送给 PlanType 绑定到该方案的全部账号；未改动的字段（例如单独调整过的优先级）和账号凭据不会被改写。只有保存前后都绑定了方案的 PlanType 才会推送；新绑定的 PlanType 和走未绑定回退规则的账号不会自动推送，需要时可筛选后重新上传。方案中清空的字段不会清空号池中的值。保存完成后，页面会提示更新数量和失败数量。
- 全局代理模式下，方案代理设置支持“使用账号原配置”、指定代理和“直连（无代理）”。指定代理被删除或过期时，上传、方案同步和号池巡检会优先使用代理配置中的备用代理；没有可用备用代理时会清除账号代理并直连。读取代理状态失败时会保留原代理。“动态登录 + 按 PlanType 授权”模式会按各 PlanType 方案独立选择授权代理；只有选用均衡分配的方案会自动分配 IP。“Sub2API 均衡分配（登录前绑定）”模式继续统一管理所有账号的代理。
- 配置方案中的 PlanType 绑定编辑器只显示当前选中的方案；切换方案后会切换到该方案自己的检测类型。底层仍保存为唯一的 `PlanType -> 方案` 映射；把同一个 PlanType 重新绑定到当前方案会覆盖原方案绑定。
- 方案中的空字段表示沿用导入文件或远端账号当前值，不会主动清空 Sub2API 已有配置；需要覆盖某个字段时填写明确值。
- PlanType 映射表保存在运行数据目录的 `plan-type-mapping.json`（权限 `0600`），前端启动时从服务端恢复；浏览器 localStorage 仅作为首次迁移来源。
- Sub2API 后端地址、号池、代理、WS mode、账号命名模板和管理员 API Key 会由本机服务保存到输出目录的 `sub2api-settings.json`（权限 `0600`）；浏览器只保留非敏感的界面缓存。更换浏览器或域名入口后，服务会自动恢复这份配置，管理员 Key 不会通过 API 返回到前端。

账号操作列中的工作空间按钮会使用单独保存的 Web 登录态，通过官方 `/backend-api/accounts/check/v4-2023-04-27` 读取可访问的组织工作空间和个人账户。弹窗会标记当前空间、个人空间、PlanType 和不可用状态；不可用空间会根据接口错误码、HTTP 状态码和错误消息区分已移出空间、空间封禁（例如 `402`）、空间停用、无权访问或未知原因，并在标签中显示识别到的代码。点击其他空间后，服务会在任务锁内重新校验授权并原子更新现有 `sub2api-import-oauth.json` 的 `chatgpt_account_id`、`account_id`、`plan_type` 及工作空间扩展字段，不会重新上传文件、创建重复账号或改动 OAuth 令牌。任务元数据中的 `workspace_plan_type` 与账号列表同步保存，因此切换后的 PlanType 会立即回显，服务重启后也不会丢失。

账号列表的 `Plan type`、`状态`、`Sub2API 号池` 和 `号池启用` 表头提供下拉筛选，并显示可编辑的远端账号 `priority`；每个筛选下拉只展示当前账号列表实际存在的值。状态筛选覆盖排队、处理中、待邮箱码、待 2FA、2FA 未通过、待手机号、待手机码、生成中、已完成、失败、封禁、待重新授权和可继续等流程状态。2FA 验证阶段被停止或验证进程中断时，任务会标记为“2FA 未通过”，保留重新授权入口，不再笼统显示为“已取消”。在号池中时，优先级单元格的数字输入和保存按钮会更新该邮箱对应的全部 Sub2API 账号记录（范围 `0-10000`）；服务会通过已保存的管理员配置读取 Sub2API 账号状态，并按账号邮箱合并到本地任务。前端约每 15 秒重新读取一次远端状态，因此在 Sub2API 管理端直接修改优先级后，列表会在下一次同步中回显；也可以通过 `GET /api/sub2api/account-status?refresh=1` 立即刷新。`号池启用` 列的开关会更新远端账号的 `schedulable` 状态。未配置或暂时无法读取后端时，状态显示为“未同步”，不会把管理员 API Key 写入浏览器。

设备查询、单设备登出、全部登出和工作空间查询统一使用账号目录中的 `web-session.json`（权限 `0600`）及固定浏览器身份。Web 访问令牌过期时，只用保存的 cookies 请求 `/api/auth/session` 更新，不调用 Codex OAuth 刷新接口；账号不匹配或 Web 会话失效时要求重新登录，不回退到 Codex 凭据。全部登出成功后清除本地 Web 会话，但保留浏览器身份。旧账号需要重新登录一次建立 Web 会话。登录成功后会在删除临时断点前独立保留 Web 会话，Codex 令牌仍单独存储在 `sub2api-import-oauth.json` 中用于号池上传和已有的授权刷新操作。工作空间切换继续同步导入文件的工作空间元数据，不改写 OAuth 令牌。

账号操作列新增“检测 Web 会话”入口，批量选中后可使用“一键登录 Web”。该流程只登录 ChatGPT Web、验证并保存 Web 会话，不请求 Codex 授权链接、不兑换或刷新 Codex 令牌、不上传或更新号池凭据；已有 OAuth 文件和原授权完成状态保持不变。没有 OAuth 文件的账号也可独立建立 Web 会话并查看工作空间。Web 登录与完整授权、令牌刷新、2FA 等任务复用同一个 FIFO 队列和任务设置中的并发上限，重复提交同一账号或提交运行中账号会被拒绝或跳过。登录方式、密码、2FA 和邮箱收码配置继续复用该账号已保存的资料；需要验证码时使用现有输入区。Web 登录使用独立的 `web-login-checkpoint.json`，不覆盖未完成的 Codex 授权检查点。取消、失败和服务重启不会把 Web 登录误判为 Codex 授权成功；排队中的 Web 登录恢复后仍是 Web-only 任务。协议命令行也可使用 `--output-mode web`，不会额外导出含 cookies 的完整会话文件。


账号列表的“Sub2API 用量”列从已配置的 Sub2API 管理接口同步 OpenAI 账号用量，不再由 toSub2 直接请求 ChatGPT 官方 `GET /backend-api/wham/usage`。普通同步读取账号列表中的 `extra.codex_*` 快照；前端约每 15 秒刷新一次，服务端状态缓存 TTL 默认也是 15 秒。前端按 Sub2API 的紧凑样式显示 `5h`/`7d` 窗口标签、已用百分比进度条和重置倒计时，不会暴露 OAuth 令牌或原始响应。点击用量旁的同步按钮会对该账号调用 Sub2API 的 active usage 接口，并把最新结果写回当前同步状态；active 查询失败时保留最近一次快照。账号名可点击复制。

状态同步还会把仅存在于 Sub2API 的 OpenAI OAuth 账号按邮箱导入本地列表，账号下方标记“仅号池”。同邮箱已有本地账号时保留本地资料，不重复创建；API Key 账号和其他平台账号不导入。同步记录在重启后保留。如果远端返回 OAuth 令牌，会保存为本地受保护的导入文件；未返回令牌时只同步账号资料和号池状态。后续为该账号补充本地登录资料后，标签恢复显示实际登录方式。

账号列表的“账号”表头提供“全部”“密码 + 2FA”和“仅号池”筛选；“密码 + 2FA”仅匹配密码登录且已记录 2FA 密钥的本地账号。“仅号池”匹配从号池同步且尚未补充本地登录资料的账号。筛选在服务端分页前执行，支持与邮箱、PlanType、状态和号池筛选组合；切换筛选时清空勾选并返回第一页。

开发与部署统一使用个人仓库 `li-zane/sub2api-helper` 的 `main` 分支。应用代码位于 x3 的 `/opt/tosub2/app`，运行数据和敏感凭据位于独立的 `/var/lib/tosub2`，不会随更新覆盖。提交并推送 `main` 后，GitHub Actions 通过 Linux/Windows 检查和依赖审计，再发布 `helper-<完整提交 SHA>`：Linux x64 / Node 22 运行包包含源码、`web/dist` 和 Node 依赖，并附 SHA256 校验。服务器执行 `helper-update` 下载并校验最新已发布版本、等待任务空闲、临时备份、切换代码和运行包后重启服务；无需在线上执行 npm 安装或前端构建。`helper-update --check` 只下载校验、不切换版本或重启；`helper-update <完整提交 SHA>` 固定到指定的已发布提交。Python 环境沿用 `/opt/tosub2/venv`，Python 依赖声明变化时预检停止，先单独准备匹配的环境。发布失败自动恢复本次临时备份，运行数据保留；发布成功后删除本次临时构建包和旧运行文件，不保留服务器历史版本。完整运维约定和脚本见 `.agents/release.md`。后续直接在个人仓库的 `main` 开发，不自动同步原项目分支。

上传选项的非敏感界面缓存仍会保存在当前浏览器的 `localStorage`（本地存储），服务端配置以设置文件为准。批量上传时，未完成的任务会自动跳过；服务端返回的各方案创建失败数量会汇总显示在控制台中。

### Sub2API 号池监控

在 Sub2API 配置中启用“状态刷新时自动恢复异常账号”后，本机服务复用每次完整号池状态刷新结果（默认每 15 秒），发现 `openai` 平台中状态为 `error` 的账号即提取邮箱、匹配本地任务并按资格加入授权队列，不再另行巡检或请求错误账号列表。如果配置了 OpenAI 或 Composite 号池，只恢复所选号池；没有选择时恢复全部 OpenAI 账号。

同一份完整状态快照还提供全部 OpenAI 账号的当前 `PlanType`，按 Sub2API 后端和账号 ID 保存上一次结果。首次看到账号只建立基线；后续发现订阅类型变化且新类型绑定了配置方案时，服务会直接调用 `PUT /api/v1/admin/accounts/:id` 更新该账号的号池、代理、并发、优先级、模型映射和账号级扩展配置，不会重新上传文件或创建重复账号。所有方案的号池会合并为恢复范围；任一方案未选择号池时按“全部 OpenAI 账号”处理。更新失败会保留旧基线，在下一次状态刷新后重试；后端列表响应不完整时也会保留旧基线。

只有同时满足以下条件的任务才会自动重新登录并授权：

- 上次完整登录已成功，且密码、邮箱验证码、登录 2FA 均未由用户手动输入。
- 上次用到的密码和 2FA 密钥仍能从系统凭据存储读取，邮箱收码 API 仍存在。
- 任务当前没有运行、排队或执行其他操作。

手动输入绑定手机号或手机验证码不影响自动修复资格，因为账号通常只需绑定一次。自动授权成功后，toSub2 会按 Sub2API 远端账号 ID 更新凭据和当前 PlanType 绑定方案，不会通过批量创建接口新增重复账号；方案中未填写的字段保留远端值，在清理授权错误后恢复调度，但保留手动停用和过载冷却的决定。

临时网络错误、代理风控、`429` 或 Sub2API 短时不可用按配置退避；异常重新授权的失败冷却默认 5 分钟，可在任务设置修改。如果登录返回明确的 `account_deactivated`、`account_deleted`、`deleted or deactivated` 或同类永久停用信息，任务状态会变为“封禁”并标记为永久跳过，下次巡检不再重试。用户仍可手动点击“重新开始授权”重新确认账号状态。

启用监控后，Sub2API 后端地址和管理员 API Key 会由本机服务保存在运行数据目录的 `sub2api-monitor.json` 中，但不会写入账号任务元数据、协议日志、状态接口或导出文件。

### OAuth 参数与会话

Codex OAuth 默认使用 `originator=codex_cli_rs`、回调地址 `http://127.0.0.1:1455/auth/callback`，以及 `openid profile email offline_access api.connectors.read api.connectors.invoke`。每次授权独立生成 PKCE 和 `state`；回调地址及 `state` 必须校验通过后才能兑换令牌。旧检查点沿用原回调地址。

可通过 `--codex-originator`、`--allowed-workspace-ids`、`--current-workspace-id`、`--codex-login-hint`、`--codex-connection` 配置登录上下文。`CODEX_INTERNAL_ORIGINATOR_OVERRIDE` 优先于命令行 originator；只有配置当前工作区才发送登录提示和 connection。

网页登录维护任务内 Cookie、来源及导航上下文；TLS 配置发生兼容性降级时同步浏览器版本信息。OAuth 令牌请求使用独立的原生 HTTP 会话和原代理配置，不发送网页 Cookie、Client Hints、Origin 或 Referer。授权码交换使用表单，刷新使用 JSON；令牌请求不自动重放，也不跟随重定向。协议参数对齐不代表本项目的 HTTP/TLS 实现与官方 Rust 客户端或真实浏览器完全相同。

验证授权与会话回归：`node test/oauth-flow.mjs`。Python 依赖版本见 `requirements.txt`；可用 `TOSUB2_PYTHON` 指向安装该版本的解释器。

## 安全说明

- `tmp/` 中包含 Cookie（登录凭证）、OAuth Token（授权令牌）和登录检查点，禁止提交或分享。
- Windows 保存的密码和 2FA 密钥由 DPAPI（数据保护接口）按当前用户加密，不会以明文写入任务目录。
- Linux 凭据文件使用 `TOSUB2_CREDENTIAL_KEY` 提供的 AES-256-GCM（高级加密标准）密钥加密，文件权限为仅服务用户可读写；生产环境应使用随机 32 字节密钥并通过 systemd（系统服务）凭据或等效 secret（密钥管理）注入。
- sub2api 导入文件包含可用的授权令牌，应当按密码文件保护。
- 凭据弹窗中的 Sub2API JSON 可能包含 access_token、refresh_token 和 id_token，仅在受保护的控制台会话中查看，不要复制到日志或聊天记录。
- 不要把 API Key、密码、2FA 密钥、验证码、Cookie 或 Token 提交到 Git 仓库。
- 网页控制台用于本机或可信局域网，不提供公网部署所需的身份认证。
- 公网反代必须在控制台前增加 Basic Auth（基础认证）、OIDC（统一登录）或 IP allowlist（IP 白名单）；`/api/bootstrap` 会返回浏览器所需的控制台令牌，不能直接暴露到公网。
- 只处理你本人持有或已获得明确授权的账号。


## 生产与会话维护

### 生产构建与 Web 状态

生产部署先执行 `npm ci && npm run build`，再以 `NODE_ENV=production` 启动服务；生产模式只提供 `web/dist` 静态页面，不启动 Vite/HMR，不公开源码路径。开发模式继续用 `npm run dev`。

账号显示独立 Web 状态：未登录、待验证、已验证、已失效；已验证表示最近 15 分钟内登录或管理请求成功，不代表凭据永久有效。令牌过期仍先用 Web Cookie 刷新，不使用 Codex 凭据兜底。可筛选 Web 状态后选择需要补登录的账号；定时巡检按开关、账号资格和暂停标记补登，不打断正在等待验证码的任务。

批量 Web 登录提供跨筛选/分页的进度、待输入及失败明细，刷新页面后同一标签页保留批次；支持仅重试失败项，跳过账号保留选择。每次登录使用独立 attempt ID，后续登录不会冒充旧批次成功。降智检测详情独立显示号池分组同步错误，不改变六格检测结论。

### 重登时复用浏览器会话与 PlanType 路由

“检测 Web 会话”和“重新开始授权”先加载该账号保存的 Cookie，在本次选定的 IP 上请求 `/api/auth/session`。已有会话有效且邮箱匹配时跳过密码、邮箱验证码和 TOTP 登录；Codex 仍执行独立授权。只有明确未登录或 HTTP 401 才使用同一 Cookie 容器重新认证；网络故障、限流、服务异常、校验响应异常及账号/设备身份不匹配会停止本次任务，不自动触发新的登录。新登录成功才原子覆盖保存的 Web 凭据；此机制减少不必要的新会话，不承诺服务端设备列表始终只有一条。

按 PlanType 授权模式下，已导入且 PlanType 已知的账号在 Web 登录、Codex 重登/刷新前应用当前方案，不再先走动态代理，也不再无条件保留与当前方案冲突的历史绑定。直连方案清除旧代理，固定方案使用当前指定节点；均衡方案复用仍有效的已绑定节点，无绑定时按已有均衡池分配；“保持原代理”继续保持原绑定。相同节点的出口 IP 变化、失效的指定节点会在登录前停止，不悄悄改成动态代理或直连。方案编辑本身不会立即重登其它账号；启用 Web 巡检与自动修复后，后续巡检可处理已确认的绑定差异。首次导入且 PlanType 未知的账号仍先动态网页登录，再依据识别到的 PlanType 选择授权代理。

## 模型指纹检测详细说明

- 顶部“降智检测设置”统一管理多模型、检测间隔、归因概率门槛、同时检测账号数和 PlanType 默认开关。账号列表可独立覆盖开关、模型和间隔，并手动检测；任务设置复用全局检测间隔和账号并发，模型、概率门槛与条件分组继续在降智检测设置管理。
- 使用 `lmfpd-sdk` 的三条数字挑战，通过该账号在 Sub2API 中的实际凭据及绑定代理发送到模型接口，在本机与公开参考库评分。账号凭据与模型回复不会提交给检测网站；仅下载公开参考数据。此请求路径直接使用账号，不经过 Sub2API 的均衡调度与用量计费统计。
- 结果区分指纹一致、疑似不一致、证据不足和请求失败。模型可写为 `请求模型 => 预期指纹名称`；不在参考库、未完成、未校准或低概率结果均为证据不足。指纹是封闭参考库内的统计归因，不是模型身份或智力证明。
- 合并参考类（例如 `gpt-6-astra/6.1-sol`）允许按其中的模型名匹配，并明确标注只归因到合并类。其它高概率参考类仍判为疑似不一致，未知模型仍保留为证据不足。
- “Codex 状态”列集中显示过载、冷却、降智开关及检测／设置按钮，下方六段状态条从左到右展示由旧到新的最近 6 轮结果：通过为绿色、不一致为红色、请求失败或证据不足为黄色，暂无记录为灰色；点击状态条可查看模型、归因、概率、候选结果和耗时。记录跨小时及服务重启保留，详情自动刷新。升级前保留的最后一轮结果可作为旧记录展示，不伪造之前未保存的历史，也不追溯更改旧结论。
- 分组规则读取各 PlanType 所绑定方案的默认分组：“默认加入”沿用原分组，“不降智加入”依据最近一轮检测，指纹或糖果任一种方法通过即可加入（本轮全部指定模型需通过）。明确未通过时移出条件组；证据不足或请求失败保留已有分组，新账号通过前不加入条件组。历史通过不会覆盖后续明确失败，检测不会改动方案之外的其它分组。
- 默认关闭且模型列表为空；每轮每个模型发送三次请求并消耗账号额度、网络和本机评分资源。默认同时检测 3 个账号，可配置 1–16；超过上限进入去重队列，同一账号的采样请求仍依次执行，排队状态可见。仅调整并发不会中断当前检测。配置、结果与最近 6 轮记录保存到输出目录的 `model-fingerprint.json`；失败分组同步会自动重试。
- 每次模型请求最长等待 180 秒；超时、连接中断和上游临时异常最多重试当前样本一次（额外消耗请求），不重跑已成功样本，不因数字样本不合格而重采样。额度不足或普通权限错误直接记录，不自动重试；401 或明确凭据失效会进入共享授权修复队列，明确封禁会停止该账号的自动化并解绑 IP。请求失败单独显示，历史保留错误分类、HTTP 状态、已完成样本和重试过程；错误不改变条件分组，旧版概括性错误保持原记录。

## 首次导入、密码轮换与记录查看

- 新账号默认先完成 Web-only 登录、识别当前空间的 PlanType 并按现有方案绑定 IP；不默认执行 Codex OAuth。
- “任务设置 → 批量导入后的自动任务”增加 **Codex 授权**。仅匹配 PlanType 的规则执行后续动作。选择上传或一键轮换上传时，会同时选中作为前置步骤的 Codex 授权；取消授权会同时取消依赖它的上传动作。只选 Codex 授权不自动上传。
- 未配置规则的首次导入完成后停留在 Web 登录完成状态；没有 OAuth 文件的账号不显示已授权或可下载。需要时可手动发起授权。
- “账号凭据”底部并排放置轮换 2FA、轮换密码按钮。封禁账号隐藏两者，对应 API 同时拒绝轮换；手动 Web 登录入口保持原规则。
- 密码轮换生成严格 **12 位**随机密码，使用系统密码学随机数并包含大小写、数字和符号。原值与候选新值在远端提交前落盘；只有上游确认完成后更新当前密码。密码、2FA 输入框清空保存仍只清除本地记录。
- 改密码的验证可能依次包含原密码、TOTP 和邮箱确认。已有 Web 登录或 TOTP 已通过不代表后续邮箱确认可以省略；缺少所需验证时停止在对应阶段，保留原记录，不把请求提交视为密码修改成功。
- 日志弹窗分为 **协议日志 / 凭据历史**，左侧选择记录，右侧按需加载详情。新协议任务分别记录；旧完整日志保留为“历史协议日志（未分组）”。
- 密码和 2FA 的原始、候选、已确认、手动清空记录全部保留。Web Session、Cookie 和 Codex OAuth 从当前规范文件读取；新版本确认保存后清理被替换的历史快照，失败候选不显示为当前有效凭据。缺失或损坏的规范文件不会触发删除唯一恢复快照。
- 2FA 历史按密钥版本合并，当前本地密钥、已确认密钥和未完成候选分别标记；重复的准备、激活、确认阶段放到版本详情中，原始记录与历史密钥仍完整保留。手动清空本地密钥保留独立记录。
- 工作空间首次成功读取及后续新增、移除、套餐、角色或可用状态变化写入凭据历史；相同列表和失败查询不重复记录。接码手机号仅在上游接受验证码后写入，附带已知的平台、国家与实际金额；取号、收到验证码、失败或取消本身不会记录为成功手机号。
- 当前密码和 2FA 是本地保存记录，不等于已证实远端已开启；详情同时标注远端状态。只有删除账号时才删除该账号的全部历史。

## 手动核对与显示时区

- 状态列的 **2FA / 密码** 可点击，分别通过已保存的 Web 会话核对远端开启状态。绿灯开启、红灯关闭、灰灯待确认；不是判断本地输入框是否有值。核对失败保留上次结果和核对时间，不自动重置密码、2FA 或执行 OAuth。账号正在执行任务、没有 Web 会话或已确认封禁时，按钮会说明暂停原因。
- “任务设置 → 显示时区”支持 IANA 时区，默认 `Asia/Shanghai`；也可使用 `UTC`、`America/New_York` 等。保存后全局页面日期、悬浮提示、记录列表和协议日志显示时间立即生效，重启后保留，并按日期正确处理夏令时。
- 新写入的协议日志每行记录 UTC 时间戳，分块输出的同一行只记录一次。切换显示时区不会修改原始日志、凭据时间戳、任务间隔、超时或按导入日期分配优先级的规则。旧日志没有时间戳的部分原样保留；凭据详情中的原始 JSON 时间值保持原样。

### Web 登录的密码入口兜底

上游进入邮箱 OTP、该账号没有配置可用的邮箱收码 API、且本地已保存密码时，Helper 会沿用本次 Cookie、设备与代理，尝试进入密码输入页 **一次**。只有确认同源页面返回密码输入框后才提交密码；已配置收码 API 或没有密码时保持原邮箱流程。上游仍要求邮箱或额外 2FA 时，保留对应验证步骤，不循环跳转，也不把中间验证页当作登录完成。日志用 `[web-password-fallback]` 标注尝试及结果；原有可用 Web/OAuth 凭据仍按现有成功后提交规则保留。

协议脚本由 Helper 启动时，通过 `TOSUB2_EMAIL_OTP_API_AVAILABLE=1/0` 接收该账号是否有收码 API 的布尔标记，不传递 API 地址或密钥。独立脚本配有外部邮箱收码器时可设置为 `1`，保持邮箱验证流程。

### 受限状态与 Codex 检测资格

“受限”依据明确的额度信号：任一用量窗口达到 100%、上游禁止使用（`allowed=false`）、限额标记（`limitReached=true`）或超额额度触顶（`overageLimitReached=true`）。金额余额为 0、数据未知或同步失败本身不等于额度耗尽；429 限流另行识别。

Codex 状态仅在 **已加入号池、号池已启用、未封禁、号池没有错误、未限流、未达到用量限额** 时允许开启。前端开关、立即检测、独立检测设置，以及后端手动 API 和后台调度统一执行这些条件。额度或 429 限流时暂停实际请求，取消活动或排队中的降智任务，同时保留原检测开关和 PlanType 继承设置；同步确认恢复后按原设置继续，手动关闭的项目保持关闭。空间仍报错、号池停用或封禁时继续暂停。已触发的过载冷却保留恢复记录并按原定时间处理。旧版本已经保存成关闭的设置会保留，需要手动开启一次，避免把用户主动关闭的任务误开。

停止检测不关闭号池账号、不改 IP、不重新登录或授权，也不停止用量和金额同步；手动用量刷新仍可使用。同邮箱多条号池记录中存在有效的达限记录时，整账号的 Codex 检测暂停。

号池列报错时直接显示上游错误码（例如 `deactivated_workspace`），悬浮可查看说明，点击可展开完整的错误码、HTTP 状态和错误消息。同邮箱有多条错误记录时一起展示。错误来自 Sub2API 的 `error_message`，兼容文本和嵌套 JSON；没有错误码时明确标注上游未提供，不根据空间或订阅状态猜测。号池恢复后清除当前错误展示。

### 账号统计与添加号池代理

顶部“正常 / 异常”统计全部账号，不随分页或筛选改变。异常只包括封禁、确认 Web 会话失效、号池错误三类；429 限流、额度用完、凭据读取失败、自动任务暂停或历史任务失败本身不计为异常。正常依据当前有效 Web 会话、正常号池状态或已完成的有效授权；未确认的账号不计入正常或异常。点击“进行中 / 排队中 / 正常 / 异常”可筛选对应账号，再次点击取消；筛选可与搜索、邮箱列表及列筛选组合，切换时返回第一页并清除选择，也可使用“清除全部筛选”。

先保存 Sub2API 后端地址和管理员 API Key，再进入“代理 IP 配置 → 添加代理”。支持手动填写名称、HTTP / HTTPS / SOCKS5 / SOCKS5H、主机、端口及可选认证信息，可设置到期时间，或快捷选择 7 / 30 / 90 / 180 天。此操作直接添加到号池的 IP 管理，适用于所有代理分配模式。

快捷导入每行一个代理，最多 100 条；支持 `host:port:username:password`、`socks5://username:password@host:port`、`username:password@host:port`、`host:port@username:password`。无协议时使用所选默认协议；URL 认证信息可用百分号编码，IPv6 使用 `[地址]:port`。解析后可逐条修改名称，再确认添加。相同端点、协议及认证信息会跳过，批量结果按条显示。网络故障导致结果待确认时先读取号池代理列表，不自动重放创建请求。

号池异常恢复与号池状态刷新共用完整快照：发现可恢复错误立即加入共享授权队列，保留账号互斥、封禁/缺少验证资料跳过与失败重试间隔，不再独立巡检或重复拉取错误账号列表。“号池异常巡检间隔”和“过载冷却检查间隔”已移除，旧设置不会覆盖当前状态刷新与次数统计频率。
