# 账号 IP 定时轮换

在“任务设置 → 账号 IP 定时轮换”启用。默认关闭，间隔默认 60 分钟，可设置 1–43200 分钟。需使用“Sub2API 均衡分配”或“动态登录 + 按 PlanType 授权”代理模式，并配置号池地址和管理员 Key。

“轮换降智账号”和“轮换未降智账号”可独立选择。使用现有降智检测中与当前模型、套餐、后端、分组规则一致的最近结果；unknown、error、尚未检测或规则变化后失效的结果跳过，不额外触发模型请求。总开关关闭时两个分类开关均不产生操作。

默认仅换绑：原位更新同一账号在号池的所有 OpenAI OAuth 记录的 `proxy_id`，逐条读取验证，再保存 helper 的绑定、固定代理 URL 和手动绑定标志。保留凭据、启用状态、优先级和分组。后续号池请求使用新 `proxy_id`，helper 后续登录和授权使用新绑定。已发出的请求保留原出口；若本地或远端写入失败，则尝试恢复原绑定，并报告尚待确认的回退。

勾选“换绑后重新登录并授权”则复用现有切换 IP 流程：选择新代理、撤销会话、进入登录授权队列，并在授权完成后同步号池。重登失败由现有任务恢复流程处理。

## 出口选择

排除账号当前使用的所有出口，以及无连接地址、过期、停启用或停止参与分配的节点。IPRoyal 已知到期的订单也跳过。按出口 IP 合并协议节点，再依次比较：

1. 当前没有绑定引用的出口优先。引用涵盖号池所有账号记录（含关闭的账号）、helper 本地绑定和有效的分配预留。
2. 历史绑定过的不同账号数量较少者优先。
3. 上次请求时间较早者优先；没有已知请求的出口视为最早。
4. 完全相同时按 IP 和节点 ID 固定排序。

全部出口都已绑定时，第一项相同，继续比较历史数量和上次使用时间。历史按实际出口汇总，同一账号重复绑定不重复计数。用量同步从号池 `last_used_at` 更新出口上次使用时间，归属窗口避免把换绑前的请求算到新出口。

选取与提交复用分配串行队列；每个到期账号都重新读取完整库存与绑定，前一个账号占用的空闲出口会在后一个账号排序时计入。号池列表不完整时停止本轮操作。

## 调度和恢复

后台每 15 秒扫描本地到期表。开启或修改轮换规则/代理模式后，等待一个完整间隔；每个账号首次出现也等待完整间隔。成功发起轮换后重排下一次时间。到期时间保存于 helper SQLite，服务重启后继续计时。

正在登录、授权、巡检会话、降智检测、冷却、暂停自动巡检或被禁用/限制的账号延后处理；重登模式额外检查登录会话和自动登录暂停状态。无可用出口或失败时最多每 5 分钟重试（间隔不足 5 分钟时使用设置的间隔）。发布暂停期间停止发起新操作，关闭服务时等待当前换绑结束。结果写入账号日志。

任务设置 API 使用嵌套增量更新，例如：

```json
{
  "proxyRotation": {
    "enabled": true,
    "intervalMinutes": 60,
    "relogin": false,
    "rotateMatched": false,
    "rotateMismatched": true
  }
}
```
