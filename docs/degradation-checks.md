# 降智检测：指纹与糖果

全局“降智检测设置”统一配置检测间隔、并发及 `modelFingerprint.testSequence`，账号可独立覆盖；任务设置不再重复提供这些选项：

```json
{
  "first": "fingerprint",
  "fingerprint": 1,
  "candy": 5
}
```

表示在每个到期检测周期内只执行一种测试，先执行 1 轮指纹，再执行 5 轮糖果，循环往复。指纹每轮、每模型需要 3 个独立样本；糖果每轮、每模型需要 1 个回答。`first: "candy"` 可反向执行；任一次数设为 0 可只执行另一种，两者不能同时为 0，每项最大 100。旧配置保持仅指纹检测。账号可独立覆盖，也可继承。

每账号独立持久化进度。正常评分（包括明确错误答案、指纹不匹配）后进入下一轮。糖果收到完整回答即消耗本轮，即使格式不合格、最终答案无法提取，也保留“证据不足”结果并推进轮换，避免永远停在同一糖果步骤；网络、认证、流中断及取消不推进。指纹样本不足仍不推进进度。账号停用、受限和封禁沿用现有调度限制。配置变化会从新规则的首项开始；修改并发不会重置进度。

糖果题保留 `jiangzhi-jiance` 的原题干与表格，来源为 [慢学测试](https://manxue.ai/)，只在结尾追加最终答案格式要求：最后一行使用 `<final_answer>整数</final_answer>`，标签内只写答案数字。完整提示词 SHA256 为 `5f563ac77205016dda33bde2b6eed30ca5d2ecf86694a43bed1cf01cfe66f5bf`；原题干 SHA256 仍为 `2ab018535731ad59fe5c3f6e4c9dbd12c40519b2b79a8a94021d1737e46ed4a2`。提示词不包含标准答案。

提取器从后往前读取最后一个 `final_answer` 标签，允许最终更正覆盖前面的推理；最后的标签若残缺、包含多个候选值或非整数，则保持未知，不借用前面的数字。未使用标签的旧式回答兼容 JSON、末尾 `\\boxed{数字}`（含 `\\text{个}`）和明确答案语句。明确最终答案 21 为通过，明确其他数值为未通过，含混回答保持未知。糖果通过仅代表此题通过，不替代模型归因。

号池条件分组统一使用“不降智加入”：最近一轮无论执行指纹还是糖果，本轮全部指定模型通过即可加入；明确未通过则移出，证据不足或请求失败保留已有分组，新账号通过前不加入。历史成功不会覆盖后续明确失败。升级时会用已保存的最近一轮有效结果重新同步分组，无需额外发起检测；账号凭据、代理、后端和 PlanType 发生变化时，旧结果不能作为新加入的依据。

## 样本不足与重试

指纹数字样本按 SDK 原规则校验，至少需要 `max(80, ceil(期望数量 × 0.55))` 个有效数字。HTTP 200、流结束但数字不足，分类为 `SHORT_OUTPUT`；流未完成为 `INCOMPLETE`，其中输出预算耗尽会附带 `max_output_tokens`。指纹和糖果共用降智检测设置中的“检测失败重试”：`failureRetries` 控制额外重试次数（默认 1，范围 0–5；0 关闭），`failureRetryDelaySeconds` 控制重试间隔（默认 5 秒，范围 1–300）。旧版 `candyRetries` 与 `candyRetryDelaySeconds` 配置自动迁移，保留已设置的数值。

指纹每轮仍需 3 份样本，糖果每轮、每个号池账号、每模型只采集 1 份完整回答，不需要三份样本或概率归因。两种方法遇到过载、网络、超时、流中断等可重试的请求失败，均等待后重试当前样本；指纹有效数字不足也按同一规则补采。重试仍占用本轮账号并发，不新增检测轮次，不重跑已经成功的样本或模型。每个指纹模型最多请求 `3 × (1 + failureRetries)` 次，糖果最多 `1 + failureRetries` 次。明确检测不通过、指纹样本已齐但归因证据不足、糖果完整回答但答案不明确均不重试；401/403、429、封禁和额度错误沿用现有停止/恢复规则。所有尝试、失败分类、回答与可获得的用量保存在同一轮详情；耗尽重试仍失败时保留轮换位置，下次到期继续。

helper 自动过载冷却只暂停号池分配和自动检测，仍可手动执行降智检测；手动检测不会提前解除冷却、延长截止时间或打开号池分配。后端按实际号池记录 ID 和当前后端核对冷却所有权，手动停用、封禁、429 或额度受限不适用此放行。冷却期间保留最近 6 轮结果的颜色、时间与详情，只有新检测记录才推进历史条。

流式回答优先读取 `response.completed` 的完整输出，其次为 `response.output_text.done`，最后为 delta。缺失结束事件仍视为未完成；所有实际请求的原题、原始回答、有效数字数、错误、完成来源及可获得的 Token 用量都写入最近 6 轮详情。没有上游用量时显示未知，有缺失时只作为已报告小计。

x3 于 2026-11-08 的只读排查发现，多份“证据不足”样本只返回 2–9 个数字并夹杂词语，例如 `247, 19, 318, 74, 161, 292, 43, em?`，旧版未针对这种已完成短回答重试。另有超时及真正的流中断记录。这些情况分开记录，不将所有未知归结为前端截断。
