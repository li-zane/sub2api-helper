# 降智检测：指纹与糖果

全局“降智检测设置”统一配置检测间隔、并发及 `modelFingerprint.testSequence`，账号可独立覆盖；任务设置不再重复提供这些选项：

```json
{
  "first": "fingerprint",
  "fingerprint": 1,
  "candy": 5
}
```

表示在每个到期检测周期内只执行一种测试，先执行 1 轮指纹，再执行 5 轮糖果，循环往复。指纹每轮、每模型需要 3 个独立样本；糖果每轮、每模型需要 1 个回答。`first: "candy"` 可反向执行；任一次数设为 0 可只执行另一种，两者不能同时为 0，每项最大 100。旧配置保持仅指纹检测。账号可独立覆盖，也可继承。

每账号独立持久化进度。正常评分（包括明确错误答案、指纹不匹配）后进入下一轮；请求失败、样本不足、取消不推进进度。账号停用、受限和封禁沿用现有调度限制。配置变化会从新规则的首项开始；修改并发不会重置进度。

糖果题直接复用 `jiangzhi-jiance` 的题干、表格与保守判分器，题目 SHA256 为 `2ab018535731ad59fe5c3f6e4c9dbd12c40519b2b79a8a94021d1737e46ed4a2`，来源为 [慢学测试](https://manxue.ai/)。题干中不包含标准答案。明确最终答案 21 为通过，明确其他数值为未通过，含混回答保持未知；错答不重试。糖果通过仅代表此题通过，不替代模型归因，也不改变按“指纹一致”管理的条件分组。

## 样本不足与重试

数字样本按 SDK 原规则校验，至少需要 `max(80, ceil(期望数量 × 0.55))` 个有效数字。HTTP 200、流结束但数字不足，分类为 `SHORT_OUTPUT`；流未完成为 `INCOMPLETE`，其中输出预算耗尽会附带 `max_output_tokens`。空回答、未能明确提取糖果答案及可重试网络/上游故障，均使用原题最多重试两次；每个指纹模型最多 9 次请求，糖果最多 3 次。认证、封禁和额度错误沿用现有停止/恢复规则。

流式回答优先读取 `response.completed` 的完整输出，其次为 `response.output_text.done`，最后为 delta。缺失结束事件仍视为未完成；所有实际请求的原题、原始回答、有效数字数、错误、完成来源及可获得的 Token 用量都写入最近 6 轮详情。没有上游用量时显示未知，有缺失时只作为已报告小计。

x3 于 2026-11-08 的只读排查发现，多份“证据不足”样本只返回 2–9 个数字并夹杂词语，例如 `247, 19, 318, 74, 161, 292, 43, em?`，旧版未针对这种已完成短回答重试。另有超时及真正的流中断记录。这些情况分开记录，不将所有未知归结为前端截断。
