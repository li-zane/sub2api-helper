# 会话、2FA 与账号日志

## 登录与更新

- 任务设置中的「登录超时」默认 3 分钟，适用于 Web、Codex 及登录相关流程；排队不计时，切换阶段不重新计时。
- Web 登录写入独立的、按尝试隔离的候选文件。验证成功后才替换正式文件；失败、取消、超时或服务中断不覆盖旧会话。
- 替换时核对原文件哈希；若它已被另一次成功刷新更新，保留最新正式会话，不用迟到的候选覆盖它。
- 会话刷新只采用身份校验通过的 token/cookie。网络错误、错误页面及其他账号的返回值不覆盖当前凭据；已验证的 cookie 轮换及时保存，即使随后读取空间失败。
- 启用 WebSession 巡检后，沿用任务设置的检查间隔，主动刷新并保存会话及 cookie。知道服务端返回的会话到期时间时，提前两分钟安排检查（最短间隔一分钟），而不是等待到期后才处理。
- 保留本地会话不等于延长服务端授权；撤销、封禁、身份验证要求或服务端过期仍会生效。有效 Web 会话也不保证通过修改 MFA 所需的近期身份验证。

## 日志与恢复历史

- 每个账号目录的 `account.log` 追加保存，不再随重登、80 KB 限制或服务重启丢弃。内存和实时界面只显示尾部，避免每秒重读整个历史文件。
- 在「协议日志」点击「完整日志与凭据历史」，可查看全部日志及原/新凭据。完整历史模式改为手动刷新。
- `credential-history/` 中的记录按事件独立保存，权限为目录 0700、文件 0600；敏感内容只由已鉴权的日志接口显式读取，不进入服务 stdout/journald 或账号列表。
- 2FA 记录包含原本地密钥、每次候选新密钥、阶段和结果。新密钥在调用激活接口前写入历史和私有结果文件，并执行 fsync。`activation_pending` 仅表示候选，不代表已激活。
- Web 更新历史保留旧会话和候选新会话。登录失败的候选记录为 `failed_preserved`；成功替换记录为 `committed`。
- Codex OAuth 导出更新也在覆盖前保留原值和候选新值。
- 清空 2FA 输入框后保存，删除当前**本地**密钥，原值保留在历史中；不会关闭远端 MFA，也不会把历史密钥自动恢复成当前密钥。
- 这些账号内历史仅随「删除账号」清理。升级前已经被截断/丢失的日志不会因此重新出现。

## 密码轮换与状态灯

- 账号凭据弹窗提供「一键轮换密码」，使用保留的 Web 会话进入上游密码修改流程；遇到近期身份验证时仍正常完成密码、2FA 或邮箱验证，不跳过验证。
- 原密码和候选新密码先写入私有历史并 fsync，随后才提交远端修改。仅在远端明确确认成功后替换本地当前密码；响应不确定时保留两者与阶段，不把候选当成已生效密码，也不自动重复提交修改。
- 密码已确认变更、但后续会话读取失败时，仍保存已生效的新密码，并保留后续失败提示。原 OAuth 文件不受密码轮换影响。
- 密码和 2FA 输入框均可复制原文；动态验证码的复制按钮仍单独保留。清空任一输入框并保存只删除本地当前值，不关闭远端密码或 MFA，也不清除凭据历史。
- 状态列显示密码与 2FA 的远端观测结果：绿灯为已开启、红灯为已关闭、灰灯为尚未确认。两项各自保存观测时间；本地输入框是否有值不作为远端开关的证据。上游未返回密码开关字段时保留已有观测，不根据缺失字段判定关闭。

## 号池上传去重

- 所有上传入口共用 backend + 规范化邮箱锁，完整覆盖列表查询、创建与更新。同邮箱不同凭据的重复批次返回冲突，不任意选一套覆盖；同邮箱的 API-key 记录不作为 OAuth 更新目标。
- 自动轮换流程等待登录收尾完成号池同步，不再额外启动第二次上传。
- 每个创建意图把原始请求与幂等键先保存到私有文件。提交结果未知时，跨重试和服务重启均重用原请求与原键；若期间凭据变化，先确认旧创建，再更新为新凭据。
- 远端记录 ID 经确认后保留。列表短暂缺项时按 ID 复核，只有所有已知 ID 明确不存在，才生成新的创建代次，支持外部删号后的正常重新上传。远端查询失败不等同于账号不存在。
- 这属于单 helper 的去重保护；多实例共享号池的原子唯一性仍由号池端约束负责。

## Codex 独立登录与自动接码

- Web session 测活成功与 Codex OAuth 完成分别记录。授权端跳转登录页时，继续原 OAuth state/PKCE 上下文中的账号识别、密码、邮箱码和 TOTP 验证，不再把它直接解释成 Web 失效并反复重登。
- 登录续接保存 `oauth_login` 检查点；手机号阶段继续沿用 `phone_required` / `phone_otp`。遇到手机号要求时显示「待手机号」，短信阶段显示「待手机码」。旧 `CODEX_AUTH_LOGIN_REQUIRED` 的界面文案修正为需要继续 Codex 身份验证，原始历史日志不改写。
- 接码平台配置增加「需要手机号时自动取号并接码」。保存后，所选平台配置持久化到服务端私有文件，关闭浏览器也能运行。旧配置仅保存在浏览器，升级后需打开接码配置、按需开启此开关并保存一次；旧配置不会静默开启付费取号。
- 开关关闭时保留原有手动「平台取号」入口；取号后仍自动收短信并提交。开关开启时，仅在实际进入手机号阶段后自动取号，再复用已有收码、提交、完成和取消订单流程。
- 每次授权最多自动取号一次；无库存、供应商错误或手机号被拒绝时显示反馈，等待明确手动重试，不循环购买。验证码不重复提交。取消或超时期间迟到的号码会释放，不会灌入新的授权任务。
- 设置或开启自动接码不会重新触发已经失败/结束的授权。已有失败账号需在更新后重新开始授权，进入手机号阶段才会启动取号。

## 会话有效期的资料边界

[所提供的 Session 刷新页面](https://cha.nerver.cc/session-refresh)描述的是用 Web session 换取 AccessToken，并要求保存返回的轮换后 session；它没有给出永久有效承诺。本项目不向该第三方发送账号会话。

[OpenAI 的会话管理说明](https://help.openai.com/en/articles/20001257-managing-active-sessions-in-chatgpt)说明了会话、设备和撤销行为，未给出所有 ChatGPT Web cookie 通用的固定有效天数。[Codex 文档](https://learn.chatgpt.com/docs/auth#login-caching)说明 Codex 自动刷新自己的登录令牌，不能据此推导 Web cookie 永久有效。

[Sign in with ChatGPT 的 Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference)公布的是该 OAuth 流程的 token 生命周期，不应直接套用到 helper 保存的 ChatGPT Web session。实际维护依赖该会话返回的 `expires`、cookie 到期信息、定期在线探测和服务端明确的失效结果。
