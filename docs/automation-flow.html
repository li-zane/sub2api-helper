核心触发联动：OAuth 凭据失效 ➔ 自动触发 Web 补登与授权恢复

当号池巡检或降智检测发现账号的 Codex OAuth 凭据失效（401 / Token Expired / Invalid Grant）时，系统自动核验 Web 会话状态： 若 Web 会话已同步过期或缺失，自动触发 Web 登录（Web 自动补登），加载已保存的密码、2FA 密钥或邮箱 API，经由专属代理完成浏览器协议登录，重新选定优先的 Team 空间；登录成功取得新 Web 会话后，紧接着无缝驱动 Codex OAuth 换票，并将新凭据回写至原有 Sub2API 账号记录，全程无需人工干预！

1. 发现 OAuth 失效 ➔ 2. 检查 Web 会话 (失效) ➔ 3. 触发 Web 自动补登 (账密+2FA+代理) ➔ 4. 核对/激活 Team 空间 ➔ 5. 完成 Codex OAuth 换票 ➔ 6. 回写 Sub2API 号池并恢复绑定

Trigger A · 异常感知
OAuth 凭据失效 / 401
号池状态刷新发现错误，或降智检测捕获 401 Unauthorized、token_expired、invalid_grant，符合恢复条件即加入授权队列。
⚡ 重点路径：将触发 Web 会话核验与联动补登！
Trigger B · 例行巡检
Web 会话周期测活
后台定时（默认 15m）使用保存的 Cookie 请求 /api/auth/session 测活，发现会话失效、缺失或绑定的空间已停用。
Trigger C · 流量指标
过载频次超过阈值
复用统一统计的 503 / overload 次数；当前固定格达到阈值，或图表累计达到 3 倍阈值，任一满足就冷却（默认 15 分钟 ≥ 10 次，或 90 分钟 ≥ 30 次）。
Trigger D · 明确封禁
账号已被永久禁用
上游任何请求返回 account_deactivated、user_suspended 等确凿永久封禁标识。

永久封禁停用

Backoff · 网络退避
临时故障与限流退避
普通 502/503 网络抖动或代理断连，保留原绑定与空间属性，不把未知套餐猜成 Free，按冷却退避重试。

关键枢纽 · Web 自动补登
Web 会话失效 ➔ 触发 Web 补登
当 Web 会话缺失或失效时，调度器自动执行协议级 Web 登录： 加载本地加密保存的密码、2FA 密钥（或调用接码/邮箱 API），通过指定代理出口完成登录，获取全新的 Web 会话 Cookie。
💡 当 OAuth 失败且 Web 会话过期时，由该节点无缝拉起登录！
快速通道 · 会话复用
Web 会话有效 ➔ 直接复用
若 Web 会话仍然有效（Cookie 正常），则跳过耗时的密码登录与 2FA 流程，直接复用当前 Web 会话，毫秒级进入下一步授权。
空间仲裁 · PlanType 核对
优先可用 Team 空间
读取多工作空间列表；若存在多个空间，优先匹配并激活可用 Team 空间；登录确认套餐变动后，自动切换绑定的代理出口方案。
↓ 驱动 Codex 授权与号池数据回写
OAuth 恢复 · Token 签发
恢复 Codex OAuth 授权
使用刚补登取得（或直接复用）的 Web 会话，发起 OAuth 授权流程，换取新鲜的 access_token 与 refresh_token。
号池同步 · 增量回写
更新原有 Sub2API 记录
将新凭据精准回写更新至 Sub2API 已有账号 ID，保留历史累计用量与绑定属性，绝不生成重复多余账号。
闭环收敛 · 巡检待命
重置状态 · 继续周期巡检
清除待修复错误标记，恢复正常调度节拍；若仅重传失败则优先重传同步，不推倒重来。

🌐 Web 会话智能巡检
保活 / 补登

使用已存 Cookie 对 /api/auth/session 进行实际测活，发现会话失效或文件缺失时自动恢复 Web 登录。

触发时机 按间隔定时扫描（默认 15 分钟），或手动点击全量巡检。
异常防护 网络断连、403/5xx 瞬时错误不误判为掉线；自动重登具备 60 分钟冷却。
🔑 OAuth 异常授权恢复
核心联动

当号池巡检或降智检测发现凭据失效时自动重新授权；若 Web 亦失效则联动触发 Web 补登。

触发时机 号池返回 401、Token 过期或降智挑战授权失败。
执行特点 优先复用有效 Web 会话；Web 失效则全自动补登；只更新已有号池记录。
🏢 设备与空间自动同步
空间仲裁

同步登录设备、可用空间与套餐快照，优先激活 Team 空间，可靠识别的 Helper 设备展示代理节点。

触发时机 随会话巡检或登录完成执行。
异常防护 设备接口临时失败不阻塞空间与套餐核对，不影响主流程。
❄️ 过载监测与自动冷却
防封保护

从号池运行日志统一读取请求与过载计数，当前固定格达到阈值，或图表累计达到 3 倍阈值，自动暂停号池调度；每账号保存独立截止时间，到期唤醒恢复。

触发时机 当前 15 分钟固定格 ≥ 10 次，或图表 90 分钟累计 ≥ 30 次（默认），任一满足。
保护机制 冷却时长（默认 60m）可配置；恢复调度绝不覆盖用户手动停用。
🎯 降智检测与条件分组
模型指纹

使用账号凭据与专属代理向模型发起探针挑战，本地指纹评分并维护号池条件分组。

触发时机 按配置间隔采样（默认 360m，1–16 并发）。
联动反馈 探针遇 401 立即派发授权修复；遇永久封禁立刻进入熔断停用。
🛡️ 封禁联动与 IP 隔离
熔断防御

一旦识别到上游确凿封禁证据，毫秒级停用号池、关闭探测、解除出口 IP 绑定，杜绝代理池污染。

触发时机 出现 account_deactivated 等永久停用特征。
执行保障 保留解绑重试与只读状态查看，彻底阻断任何后续自动重登。
🔍 查看【OAuth 失败联动 Web 补登】的内部详细时序 展开 ▾

1. 捕获失效：Sub2API 号池巡检发现账号处于 status: error 且返回 token_expired 或 invalid_grant，或模型降智采样返回 HTTP 401。

2. 资格与防抖审查：系统调取 getAutoRepairEligibility(job)，检查是否已保存该账号的完整密码、2FA 密钥或邮箱 API。若处于冷却中或缺少凭据，则只打标签等待人工介入，避免无序重试。

3. Web 会话探活：调度器首先调用 probeAccountWebSession(job) 校验本地缓存的 Web Cookie。若 Web 仍然有效，直接生成 OAuth 链接并换票，跳过耗时的全登录流程。

4. 联动触发 Web 补登：若 Web 会话已失效，由 forceReloginJob(job, ..., { autoRepair }) 拉起浏览器底层协议登录，绑定账号设定的专属代理出口，自动填充密码并通过 2FA 校验。

5. 空间与套餐重构：登录成功后，读取 /backend-api/accounts/check，自动匹配最佳可用 Team 空间并重构 Web Session。

6. 授权换票并增量回写：调用 startOAuthFromWebSession() 签发新 Access/Refresh Token，通过 createSub2ApiAutoRepairOperation() 将新凭据精准 PUT 回 Sub2API 原账号 ID，同步刷新 PlanType 与 IP 绑定。
